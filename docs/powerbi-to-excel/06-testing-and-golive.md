# 六、测试与上线

## 1. 小样测试

先把 DAX 换成 [`dax/smoke_test_topn.dax`](dax/smoke_test_topn.dax)（`TOPN(10, ...)`），
跑通"取数 → 解析 → 写入"的全链路后，再替换为正式查询放开全量。

## 2. 上线前检查点

- [ ] DAX 字段引用是否加了方括号：`item()?['[销售额]']`。
- [ ] 数值是否用 `float()` / `int()` 转换，写入后在 Excel 中是否右对齐（右对齐=数值）。
- [ ] 时间是否用 `convertFromUtc(..., 'China Standard Time', ...)`，没有 8 小时时差。
- [ ] Excel 表名是否为 `TB_Log`，且动作里选中的是表格而不是工作表。
- [ ] `Recurrence` 触发器的时区是否设为 China Standard Time。
- [ ] 重跑一次流，确认没有产生重复行（幂等生效）。
- [ ] 人为制造一次失败（如改错 Dataset ID），确认 Catch 分支能发出通知。

## 3. 性能验证

- 记录一次完整运行的耗时，与数据量增长后的预估耗时。
- 确认单个动作不超时：`Run a query against a dataset` 约 10 分钟上限，
  HTTP 请求约 2 分钟上限（超过需改异步模式）。
- 若逐行写入耗时超过几分钟，改用 Office Scripts 批量写入。

## 4. 权限交接

- **不要用个人账号建生产流的连接**：账号离职、改密、启用 MFA 策略变更都会导致连接失效。
- 建议做法：
  1. 使用专用**服务账号**（有 Power BI Pro 许可 + 语义模型 Build 权限）建立连接。
  2. 把流放进 **Solution（解决方案）**，通过 Dataverse 管理与迁移。
  3. 给流添加**共同所有者**（至少 2 人或一个安全组），避免单点。
  4. Excel 文件放 **SharePoint 文档库**而不是个人 OneDrive（个人 OneDrive 会随账号注销消失）。

## 5. 监控

- 在 Power Automate 中开启**流失败通知**（默认会给所有者发邮件摘要）。
- Catch 分支主动推送 Teams / 邮件，正文包含 `workflow()?['run']?['name']` 便于定位运行。
- 每周检查一次运行历史，关注：失败次数、平均耗时趋势、写入行数是否异常为 0。
- 可额外建一个"哨兵流"：每天检查 `TB_Log` 中是否存在昨天的行，没有则告警
  （能捕获"流成功但数据为空"这类静默故障）。

## 6. 环境推广

开发 → 测试 → 生产建议通过 Solution 导出/导入，并把
Workspace ID、Dataset ID、文件路径、收件人邮箱等做成**环境变量**，
避免在不同环境中手工改动作参数。
